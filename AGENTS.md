# Smash & Dash — how to reach the running game

Agent tools (map and decisions: `docs/agent-map.md`, `toolsmith/decisions.md`; the engine's: `external/ska/AGENTS.md`). Use them before writing an ad-hoc script, a sleep or asking the human to play. `tools/doctor` runs them all against the real game (also in CI).

- `tools/sad-run up <id> [--save NAME] [--seed N --fixed-step --pause-at N] [--env SAD_BATTLE_AUTOPLAY=1]`: the game in its own run folder, on a virtual display, from a **copy** of `Data/Saves/<NAME>` (default `save1`: its world, seed 7, an infinite world, its start written in the copy on the loading screen, about 5 s, the rest as the player comes; it starts on `w_253_247`; `save2`: another world, seed 42, `w_253_256`; `SAD_SAVE_DIR`, `SAD_SAVE`): a run never writes the saves of the repository; `up` returns once the game plays the save (or is paused). A NAME with no save there is a new game (`--env SAD_WORLD_SEED=N`, else a random seed). `--title`: the title screen (no save given; console `ping` only, no script VM before a save is played; W/S, Return). Ready when the console runs skalang. `tools/sad-run down <id>`, `ps`, `logs <id> --grep ...`.
- `external/ska/tools/ska-console [--run ID] eval '<skalang>'`: in the live game, with `Engine`, `Dev`, `GameDialog`, `Character`, `Map`, `Party`, `Interface`, `Battle`, `Save`, `Bag` imported. Ex: `eval 'Map.name()'`, `eval 'Party.hp(0)'`, `eval 'Engine.setVariable("%00012", 1)'`.
- Agent scripts (`ska-console run <file> args`, `ska-console scripts` lists them): `tools/agent/warp.miniska <map> <x> <y>` (a block of that map; waits for it, and replies the block in the map then in the world outdoors, `w_253_247 (38,20) world (10158,9900)`; any chunk of the infinite world, written at once when it is not yet (a new region : about 1.5 s); the rooms are named by their door, `w_room_<x>_<y>`, ex : `w_room_10127_9882 11 8` in save1; it does not check the block: warped onto a wall (a tree, a cliff), the player cannot move, so pick a walkable block), `battle.miniska <monster id> <level>` (waits for the end; unattended with `SAD_BATTLE_AUTOPLAY=1`: the AI plays both sides, the battle messages close by themselves), `party.miniska`, `wild.miniska` (the wild Pokemon of the chunks loaded: monster, level, block of the world, attitude; a warp keeps them with their chunks: `ska-run logs <id> --grep "Chunk "` shows the chunks coming, leaving and their entities back), `eval 'Party.move(2, 0)'` (the order of the team), `eval 'Party.skills(0)'` (its moveset), `press Tab` (the menu of the trainer: W S A D, Return, Escape), `press F3` (the debug panel; `--env SAD_DEBUG=1`: shown at the start), `eval 'Battle.clash()'` during a battle (a clash now: the impact, the screen "VS", the battleground, 3 rounds; `ClashSystem`, drawn by `ClashArena`), `spawn.miniska <monster id> <level>` (a wild Pokemon arrives near the player as the rules want it: 16 Roucool flies in, 19 Rattata comes out of a hideout, the others walk in; then `wild.miniska`), `variables.miniska [prefix] [all]`, `walls.miniska [width height [x y]]` (the walls as the physics sees them, in blocks of the world: `.` free, `#` a wall, a character or a chunk not loaded); engine: `external/ska/tools/agent/state.miniska`, `entities.miniska <name>...`. They are checked by the build like the game scripts.
- Tiles: `tools/worldgen/tileroom.py <run folder>/Saves/save1/World` writes the map `w_tiles` in the world of a run: every tile of the generator (objects, trees, buildings, grounds, cliffs, water, furniture), placed by its code, and the block to stand in front of each (`warp.miniska w_tiles X Y`). It fails when a kind of tile the generator draws is not shown (place a new tile there). `--walls <reply of walls.miniska 52 54> --at X Y`: the walls of the game against the blocks the generator made walkable (`tools/doctor` runs both).
- See and act: `ska-console shot <name>` (PNG of the frame), `press <key> [steps]` (map keys: W A S D, Return action, Space jump, 1-4 skills), `pause`, `step N`, `resume`.
- Slow frames: `--env SKA_PROFILE=30 --env SKA_VSYNC=0`, then `logs <id> --grep "Profile :"` (the engine's `Profiler`: each system, each drawing, the present; the game times the parts of the interface: `ui text`, `ui panel`, `ui image`, `ui fill`).
- Replay a battle: two runs `--seed 7 --fixed-step --pause-at 120 --env SAD_BATTLE_AUTOPLAY=1`, `run tools/agent/battle.miniska 25 3` then `resume` in each, `ska-run logs <id> --grep "Battle t=" --strip --tail 0`: the traces are identical.
- Web: `tools/web/sad-web up <id> [--env SAD_X=1]` (needs `tools/web/build.sh` and `npm install --prefix tools/web`): the web build in headless Chromium on 127.0.0.1, its own saves; `shot`, `press`, `console`, `eval`, `down`. `tools/web/serve.sh` (it serves the whole network) only when the human asks for it: the harness asks for approval each time.
